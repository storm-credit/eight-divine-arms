## 1. 감사 목적

저장소에는 초기 Gate 문서, 대안 비교 문서, 폐기 전 주인공 프레임, 1000화 기능표가 함께 남아 있다. 이들을 삭제하지 않으면서 현재 진행 상태로 오인되지 않도록 권한을 분리한다.

## 2. 발견된 고위험 혼선

### README 상태 불일치

기존 README는 다음을 현행 상태로 표시했다.

- Gate 2 진행 중.
- Gate 3~5 차단.
- 세력 아키텍처와 팔대신병 기원 가설이 우선 작업.

현재는 캐릭터·관계·세계·팔대신병·8부 플롯·복선·연속성·960화 제작 오버레이·통합 QA까지 완료된 PM 후보 상태이므로 위 표시는 폐기된 진행 좌표다.

조치: README를 최신 대시보드와 동결 Manifest 중심으로 교체한다.

### `human-edit-pending` 잔존

검색 결과 여러 구문서와 기존 기능표에 `human-edit-pending`이 남아 있다. 이 태그는 해당 파일 작성 당시의 상태이며 현재 프로젝트 전체 상태를 뜻하지 않는다.

조치:

- 구문서의 본문을 일괄 변경하지 않는다.
- 최신 대시보드·완료 색인·동결 Manifest가 프로젝트 상태를 덮어쓴다.
- 기존 10화 기능표는 사건 원본으로만 사용하고 960화 오버레이를 적용한다.

### `provisional-canon` 잔존

README, 초기 Gate, 검증 문서, 과거 타임라인 등에 `provisional-canon`이 남아 있다.

판정:

- 당시 단계 기록으로는 보존 가능.
- 현재 사용자 정본을 뜻하지 않는다.
- 최신 PM 후보 상태보다 우선할 수 없다.

## 4. 충돌 해결 규칙

1. 최신 사용자 결정이 모든 문서보다 우선한다.
2. 사용자 결정이 없으면 `book_writing.md`를 따른다.
3. 현재 완료 상태는 대시보드·완료 색인·동결 Manifest로 판단한다.
4. 인물·신병·복선·적대 구조 세부값은 최신 장기 장부를 따른다.
5. 1000화 기능표의 사건은 보존하되 화수·이름은 960화 오버레이로 읽는다.
6. 구문서의 상태 태그만으로 설정을 복원하거나 정본 승격하지 않는다.

## 5. 잔여 미정의 성격

현재 미정은 설계 누락이 아니다.

- 후보 이름과 명칭의 사용자 승인·거부.
- 로맨스 사용 여부와 강도.
- 플랫폼·계약 최소 분량.
- 정본 승격.
- 집필 준비 승인.

따라서 자동 진행이 위 미정을 이유로 새 대안을 계속 생성하지 않는다.
