# 오픈소스 장편 설계 본보기 검토 v1

상태: `reference-complete / no-code-copied`
총괄: PM 오케스트레이터
적용 Gate: 플롯 재설계 v3

## 1. 목적

유사 오픈소스의 작품 조직 방식을 참고해 플롯 재설계 문서를 더 작고 추적 가능하게 만든다. 애플리케이션 코드·문구·고유 양식을 복사하지 않고 정보 구조만 추상화한다.

## 2. 참고 1 — `vkbo/novelWriter`

확인한 특징:

- 장편을 여러 작은 인간가독 텍스트 문서로 구성
- 주석·시놉시스·교차참조 메타데이터 분리
- 버전 관리와 파일 동기화에 적합한 저장 구조

이번 적용:

- 맹점·프리모텀·후보·승인·정본을 별도 파일로 분리
- 각 문서 헤더에 상태·상위 기준·Gate 기록
- 긴 Outline은 막·구간별로 나눠 저장

가져오지 않음:

- novelWriter 고유 문법
- 프로그램 UI와 애플리케이션 코드
- 원고 작성 단계의 기능

라이선스 확인:
- GPLv3

## 3. 참고 2 — `andreafeccomandi/bibisco`

확인한 특징:

- premise·fabula·narrative strands·settings·characters·chapters·scenes를 구분
- 인물의 복잡성을 플롯과 별도 층에서 검토
- 수정과 리비전을 별도 단계로 관리

이번 적용:

- 설정·인물 프레임은 유지하고 플롯 골격만 재개방
- 네 시안마다 `주인공 욕망`, `대서사 행동축`, `적대 추적선`, `결말 비용`을 분리
- 승인되지 않은 시안을 Outline과 분리

가져오지 않음:

- UI 메뉴를 그대로 문서 폴더로 복제
- 모든 인물 항목을 동일 분량으로 채우는 방식
- 장면 단계의 조기 개방

라이선스 확인:
- GNU GPL

## 4. 참고 3 — `olivierkes/manuskript`

확인한 특징:

- 한 문장 premise를 문단·전체 요약으로 단계 확장
- 인물·플롯·Outline·세계·중요 항목을 분리 추적
- Outline과 index card를 별도 단계로 사용
- story line과 중요 item tracking 제공

이번 적용:

- 네 시안을 먼저 한 줄 대서사로 비교
- 선택된 안만 막·구간·장 단위로 확장
- 팔대신병·부상·단서·권리를 별도 연속성 장부로 추적
- 장면 카드와 원고는 Outline 통과 뒤까지 잠금

가져오지 않음:

- Snowflake 또는 특정 작법을 유일 정답으로 채택
- 모든 장을 현재 단계에서 카드화

라이선스 확인:
- GPL v3 이상

## 5. 이번 Gate에 적용한 공통 패턴

1. 작은 파일과 명시적 상태
2. 전제→대서사→Outline의 단계 확장
3. 인물·플롯·세계·중요 물건의 분리 추적
4. 리비전 상태와 승인 상태 분리
5. 선택되지 않은 후보를 정본과 분리
6. 원고·장면 단계의 조기 개방 금지

## 6. 적용하지 않을 패턴

- 앱의 데이터 모델을 작품 설계에 그대로 이식
- 양식 칸을 채우기 위한 설정 과잉
- 소프트웨어 기능을 설계 품질로 착각
- 오픈소스 예시의 플롯·문구·코드 복사

## 7. 판정

> 오픈소스는 작품 내용을 제공하는 본보기가 아니라, 단계·상태·교차참조·추적 문서를 조직하는 본보기로만 사용한다.
