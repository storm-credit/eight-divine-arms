# 《팔대신병록》 자율 설계·메타 프롬프팅 프로토콜 v1

상태: `active-protocol / CLAUDE.md-extension / manuscript-locked / canon-promotion-locked`

이 문서는 `CLAUDE.md`의 오케스트라·자동 진행·중지 Gate를 보강한다. 충돌 시 최신 사용자 발언, `book_writing.md`, `CLAUDE.md` 순서를 우선한다.

## 1. 자동 진행의 의미

사용자의 `자동으로`, `진행`, `이어서`, `끝까지 계속`은 추가 승인 질문 없이 다음 작업을 반복 수행하라는 뜻이다.

1. 현재 저장소와 최신 사용자 결정 동기화
2. 남은 설계 공백 탐색
3. 구현 전 함정 점검
4. 대안 설계 4안 비교
5. 참고 작품·공개 자료 조사
6. 최적안 통합
7. 독립 전문가 검토와 레드팀 반박
8. 결과물 점검과 문서 동기화
9. 계획 이탈·막힘 기록
10. 다음 미완료 작업으로 이동

다만 후보의 `canon` 승격, 원고 집필, 확정 설정 변경은 사용자 명시 승인 전 금지한다.

## 2. Karpathy식 실행 원칙

- 먼저 문제와 성공조건을 한 문장으로 고정한다.
- 복잡한 설계는 작은 검증 단위로 나눈다.
- 가정과 확정 사실을 분리한다.
- 가장 단순하게 작동하는 구조를 우선한다.
- 멋있지만 검증되지 않은 설정을 늘리지 않는다.
- 결과를 만든 뒤 반드시 실패 사례와 반례를 점검한다.
- 문서가 실제 실행 규칙과 어긋나면 문서를 즉시 동기화한다.

외부 저장소의 문장이나 코드를 복사하지 않고, 문제 분해·검증·피드백 루프의 작동 원리만 참고한다.

## 3. 구현 전 함정 체크

설계에 들어가기 전에 최소한 다음을 확인한다.

- 사용자의 최신 의도와 충돌하는가
- 기존 8액트·960화 인과를 깨는가
- 남성 서유휘 단일 주인공성이 약해지는가
- 수집 보상이 설명보다 늦어지는가
- 새 보물이 기존 보물을 폐기시키는가
- 같은 비경·경매·추적·복원 공식이 반복되는가
- 게임 시스템 냄새가 정통 무협 감각을 압도하는가
- 인물의 욕망 없이 설정만 움직이는가
- 후반 회수를 위해 초중반 재미를 희생하는가
- 이름·화수·소유·부상·이동·정보 공개가 충돌하는가
- 참고작과 장면·인물·반전·고유 조합이 지나치게 유사한가

P0 구조 오류가 있으면 설계를 진행하지 말고 먼저 수정한다.

## 4. 디자인 시안 4개

중요 설계마다 한눈에 비교 가능한 네 가지 안을 만든다.

1. **정통안**: 무협 감각과 사승·문파·강호 인과를 최우선
2. **연독안**: 웹소설 속도·보상·다음 화 기대를 최우선
3. **수집안**: 보물·비급·신수·장인·도감의 수집욕을 최우선
4. **반전안**: 익숙한 공식을 비틀되 기존 약속을 훼손하지 않는 안

각 안은 다음 다섯 항목으로 비교한다.

- 독자 핵심 가치
- 즉시 보상
- 장기 회수
- 위험과 비용
- 기존 설계와의 호환성

PM은 한 안을 그대로 고르지 않아도 되며 장점을 통합할 수 있다. 단, 통합안이 네 안보다 흐려지면 가장 강한 단일안을 채택한다.

## 5. 사용자 인터뷰 원칙

이미 확인된 사실은 다시 묻지 않는다. 질문은 다음 경우에만 한다.

- 사용자 취향에 따라 결과가 완전히 갈리는 핵심 선택
- 상위 문서끼리 충돌하며 저장소만으로 판정할 수 없는 경우
- 정본 승격 또는 원고 개방처럼 중지 Gate를 넘는 경우

질문이 필요할 때는 추상적인 취향 대신 실제 결과를 바꾸는 한 가지 선택만 묻는다. 자동 진행 지시가 있으면 사소한 공백은 합리적 가정과 후보 표시로 처리한다.

## 6. 본보기 조사 원칙

GitHub와 공개 자료에서 유사한 장르 설계·장기 플롯·캐릭터 아크·수집 구조·에이전트 워크플로를 조사할 수 있다.

소설 참고 시에는 다음만 추출한다.

- 독자 욕망을 여는 방식
- 보상 간격과 기대 관리
- 장기 복선 배치 방식
- 인물 관계의 갈등 구조
- 수집품이 사건과 전투를 바꾸는 원리
- 시즌·액트·에피소드의 기능 분배

복사 금지 항목:

- 고유 인물 조합
- 장면 순서
- 대표 대사
- 고유 반전
- 세계관 명칭
- 핵심 장치의 동일한 결합

모든 참고는 `참고한 작동 원리 / 변형 방식 / 복제 위험 점검`으로 기록한다.

## 7. 메타 프롬프팅 3단계

### 7.1 컨텍스트 덤핑

작업 전 필요한 맥락을 모은다.

- 최신 사용자 결정
- 목표 독자와 장르 약속
- 현재 설계 상태
- 관련 정본·후보 문서
- 반드시 보존할 사건
- 금지사항과 중지 Gate
- 이미 발생한 충돌과 실패

### 7.2 프롬프트 깎아내기

초기 지시에서 중복·추상어·충돌을 제거하고 아래 구조로 압축한다.

- Goal
- Reader value
- Inputs
- Must preserve
- Must change
- Constraints
- Success conditions
- Validation
- Stop conditions
- Deliverables

### 7.3 결과물 점검

결과를 다음 순서로 검사한다.

1. 사용자 의도 충족
2. 재미와 연독성
3. 수집 보상
4. 인물 주도성
5. 무협 감각
6. 장기 인과와 복선
7. 전투에서의 실제 차이
8. 반복과 설명 과부하
9. 연속성
10. 복제 위험

검사 실패 시 결과를 확정하지 않고 수정 루프로 되돌린다.

## 8. 작업별 프롬프트 변환

### Goal Prompt

- 목표와 독자 가치를 먼저 명시한다.
- 완료 조건과 중지 조건을 명시한다.
- 무엇을 만들지뿐 아니라 무엇을 만들지 않을지도 적는다.

### 장기 설계·Ultra 작업

- 화수·액트·문서 우선순위·캐논 상태·금지 설정을 제약조건으로 고정한다.
- 한 번에 무한 확장하지 않고 현재 병목부터 해결한다.
- 검증 가능한 산출물 단위로 분리한다.

### 이미지 생성

이미지가 필요한 경우 구도·피사체·스타일·조명·카메라 방향·화면비·금지 요소를 명시한다. 이미지가 설계 문서의 사실을 임의로 확정하지 않게 한다.

### 리서치 에이전트

- 1차 자료와 신뢰도 높은 출처 우선
- 조사 범위와 날짜 명시
- 사실·해석·추론 분리
- 최소 2개 독립 출처로 핵심 주장 교차검증
- 소설 참고 시 작동 원리만 추출하고 복제 위험 검사

## 9. 계획 이탈·막힘 기록

원래 계획과 달라졌거나 막혔을 때 아래 형식으로 기록한다.

- 작업 목표
- 원래 계획
- 실제로 발견한 문제
- 왜 계획이 바뀌었는가
- 채택한 우회안
- 버린 대안과 이유
- 영향받는 문서·액트·화수
- 남은 위험
- 다음 검증 항목

숨기거나 결과만 덮어쓰지 않는다. 구조적 변경은 별도 결정 로그 또는 감사 문서에 남긴다.

## 10. 성공조건

설계 완료 후보는 최소한 다음을 만족해야 한다.

- 1~10화 안에 작품의 핵심 가치가 보인다.
- 각 10화 묶음에 사건·감정·보상·다음 의문이 있다.
- 모든 수집품이 능력·장소·인연 중 하나 이상을 연다.
- 서유휘의 선택이 사건 결과를 바꾼다.
- 팔대신병과 하위 수집축이 단계적으로 기대를 키운다.
- 전투에서 병기와 무공의 차이가 장면으로 드러난다.
- 8액트와 960화의 인과·부상·이동·정보 공개가 연결된다.
- 결말 보상이 초반 약속과 이어진다.
- P0 오류가 0이고 P1에는 완화책이 있다.
- 후보·확정·폐기 상태가 문서에서 구분된다.

## 11. 자동 반복 루프

`탐색 → 함정 체크 → 4안 → 통합 → 전문가 검토 → 레드팀 → 수정 → QA → 문서 동기화 → 다음 공백 탐색`을 반복한다.

새 설정을 만들 필요가 없으면 추가 창작을 멈추고 다음으로 전환한다.

- 중복 제거
- 구버전 오염 제거
- 인덱스 정리
- 화수·인물·아이템 상태 동기화
- FUN·반복·고증·복제·연속성 감사
- 완료 후보 보고

## 12. 참고 워크플로의 역할

- Karpathy Guidelines: 단순화·가정 분리·검증 루프
- Superpowers: 구현 전 설계·독립 검토·작업 분해
- Understand-Anything: 저장소 전체 구조 파악과 영향 범위 추적
- agentmemory: 사용자 결정·실패·변경 이력의 지속적 회수
- claude-video류 워크플로: 산출물 제작 단계를 명시하고 결과 검증을 자동화하는 방식

외부 프로젝트를 그대로 설치해야만 이 프로토콜이 작동하는 것은 아니다. 필요한 원칙을 현재 소설 설계 저장소에 맞게 변환해 사용한다.
